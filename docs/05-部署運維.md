# JobFly 部署與運維指南

- 文檔版本：v0.2（更新：認證代理架構、Render 綁卡要求、網絡封鎖實測）
- 目標：免費層內把整套系統部署到生產，並可持續運維

## 0. 實測網絡結論（重要）

| 目標 | 本機網絡實測 | 影響與對策 |
|---|---|---|
| *.supabase.co（auth/REST 邊緣） | ❌ 連接被重置 | **前端不直連 supabase.co**，登錄/註冊走後端「認證代理」（/api/auth/*），後端部署在美區可正常訪問 |
| db.*.supabase.co（Postgres 直連） | ✅ 正常 | 遷移/集成測試可直接跑 |

| github.com（git 端口） | ❌ 超時 | 同上 |
| api.render.com | ✅ 正常 | API 全自動部署（scripts/render_deploy.py） |
| Workday | ❌ 區域封鎖 | Worker 部署美區（ohio） |

## 1. 架構總覽（免費層）

```
用戶瀏覽器 ─▶ 前端靜態站（Render Static Site）
                │  HTTPS + 後端簽發會話（瀏覽器不碰 supabase.co）
                ▼
       後端 API（Render Web Service，美區 ohio，Docker）
       ├─ 認證代理：/api/auth/* → Supabase Auth（服務端轉發）
       ├─ APScheduler：每日採集 / 投遞隊列 / 摘要推送 / 心跳
       ├─ Playwright Chromium（鏡像內置 /ms-playwright）
       └─ LLM API（DeepSeek）
                │
      ┌─────────┼──────────────┐
      ▼         ▼              ▼
  Supabase    Cloudflare R2   PushPlus/企業微信/SMTP
  (500MB)     (10GB 附件)
```

## 2. Supabase 初始化（管理員）

1. [supabase.com](https://supabase.com) 註冊 → New project（區域選離用戶近的，如新加坡/東京對亞太延遲低；**注意採集 Worker 在美區，DB 區域不影響 Worker 訪問 Workday**）→ 記住 DB 密碼。
2. Dashboard → Project Settings → API：記下 `Project URL`、`anon public key`、`service_role key`。
3. Database → Connection string：取得直連 `DATABASE_URL`（postgresql://postgres:[PASSWORD]@db.[REF].supabase.co:5432/postgres）。
4. Authentication → Providers → Email 開啟；**Sign In** 中開密碼登錄（或魔法鏈接）；若要用大陸手機號登錄需自建短信商（見 R9）。
5. 執行遷移（管理員本機或 CI）：
   ```bash
   cd backend
   DATABASE_URL=postgresql://... alembic upgrade head
   ```
6. 在 Auth → Users 手動創建管理員帳號（郵箱與 `ADMIN_EMAILS` 一致），首次登錄自動獲得 admin 角色。

## 3. Cloudflare R2（附件存儲）

1. Cloudflare Dashboard → R2 → Create bucket（如 `jobfly-documents`）。
2. 生成 API Token：Manage R2 → API Tokens → Object Read & Write → 限定該桶。
3. 記錄：`R2_ACCOUNT_ID`（Dashboard URL 中）、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`。

## 4. 推送渠道

| 渠道 | 獲取方式 |
|---|---|
| PushPlus（用戶自助） | [pushplus.plus](https://www.pushplus.plus) 註冊實名 → 個人中心拿 token → 用戶在「投遞設置」頁自行填寫 |
| 企業微信群機器人（管理員告警） | 企業微信群 → 群機器人 → 複製 webhook URL → 填入後端 `WECOM_WEBHOOK_URL` |
| 郵箱 SMTP | 任一 SMTP（Brevo/QQ 郵箱授權碼）→ 填入 `SMTP_*` |

## 5. 後端部署（Render，美區）

> ⚠️ Render 新帳號創建任何服務（含免費）都要求先綁定付款方式：
> Dashboard → Billing → Add card（免費額度不會扣費，僅帳號驗證）。

1. 綁卡後，用腳本一鍵部署：
   ```bash
   export RENDER_TOKEN=rnd_xxx
   python scripts/render_deploy.py   # 自動：建後端(Docker,ohio)+前端(靜態站)+注入密鑰+回填跨域
   ```
2. 或手動 Blueprint：Render → New → Blueprint → 連接 GitHub 倉庫 → 用 render.yaml
   （render.yaml 中密鑰為 sync:false，需在控制台手填）。
3. 環境變量清單見 `backend/.env.example`（多了 `SUPABASE_ANON_KEY`，認證代理使用）。

## 6. 前端部署

前端已不依賴任何 Supabase 環境變量（認證走後端代理）。
- 自動：scripts/render_deploy.py 一併創建靜態站（build: `npm install --prefix frontend && npm run build --prefix frontend`，publish: `frontend/dist`）。
- 手動：Render Static Site / Vercel / Netlify 均可，構建命令同上，無需任何環境變量。
- 部署後域名回填後端 `FRONTEND_URL`（跨域與推送連結，腳本已自動處理）。

## 7. 保活（免費層防休眠）

- UptimeRobot（免費）監控 `https://後端域名/healthz`，5 分鐘間隔：
  - 防 Render 免費實例冷啟動
  - 防 Supabase Free 無活動 1 週休眠（後端每 6 小時心跳也會查庫，雙保險）

## 9. 日常運維

- 每日看一次管理後台 stats：投遞成功率、待人工任務積壓、帳號異常。
- 適配器連續失敗 → 看 `last_error`，多數是頁面改版，更新選擇器即可（選擇器集中在 `app/apply/*` 與 `app/collectors/*` 頂部）。
- LLM 成本：stats 頁 token 計數；DeepSeek 等按量計費，每月核對賬單。
- 備份：Supabase Free 無自動備份 → 建議每月手動導出（Dashboard → Database → Backups 或 `pg_dump`）。
- KEK 輪換：暫不支持自動輪換；若 KEK 洩露，需全量重設用戶平台帳密。

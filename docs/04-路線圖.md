## 3. 風險登記冊

| 編號 | 風險 | 概率 | 影響 | 緩解 |
|---|---|---|---|---|
| R1 | 獵聘/Boss 風控封號 | 高 | 高 | 首期不碰；二期半自動 + 行為模擬 + 速率限制 |
| R2 | ATS 頁面改版導致適配器失效 | 高 | 中 | 適配器健康監控 + 自動告警；選擇器集中配置；每日冒煙測試 |
| R3 | 免費層配額超限（Supabase 休眠/存儲滿） | 中 | 中 | 心跳保活 + 數據壓縮/清理策略 + 升級路徑 |
| R4 | 用戶帳密安全事件 | 低 | 極高 | 信封加密 + 脫敏日誌 + 審計 + 合規三件套 |
| R5 | LLM 編造簡歷內容 | 中 | 高 | 只重組已有事實；微調 diff 摘要審計；關鍵字段人工確認 |
| R6 | 驗證碼/登錄失效打斷自動投遞 | 高 | 中 | 人工接管通道（設計上把打斷變為可控流程） |
| R7 | 重複投遞同一公司 | 中 | 中 | unique(user_id, posting_id) + 公司級去重規則（可配） |
| R8 | 第三方平台條款禁止自動化 | 高 | 高 | 官網/ATS 直接申請頁為主；操作頻率擬人化；法律文件免責聲明 |
| R9 | Supabase Auth 手機短信在中國大陸不可用 | 中 | 低 | 郵箱登錄為主；手機號僅作備用（或用自有短信商） |
| R10 | Workday 等 ATS 對部分亞太 IP 區域封鎖（實測：本機網絡被 302 到維護頁） | 高 | 高 | 採集/投遞 Worker 部署在美區（Render US/Railway US）；API 與前端可留任一區域 |

## 4. 需要你配合提供的事項

1. Supabase 帳號（管理員）→ 我出初始化 SQL，你執行或授權我操作；
2. Cloudflare 帳號（R2 桶 + API Token）；
3. 部署平台帳號（Render 或 Railway）；
4. LLM API key（DeepSeek/OpenAI 兼容任選）；
5. 平台推送渠道註冊：PushPlus（實名）、企業微信機器人 webhook、郵箱 SMTP 授權碼；
6. 三份法律文檔（用戶協議/隱私政策/代投授權書）——我出草案，建議找專業人士審。

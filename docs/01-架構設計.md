# 求職簡歷自動投遞系統 — 架構設計

- 文檔版本：v0.1
- 關聯文檔：《00-需求規格》《02-數據模型》《03-免費服務選型》《04-路線圖》

## 1. 總體架構

```
                        ┌─────────────────────────────────────────────┐
  求職用戶 ──瀏覽器──▶  │  React SPA (Vite)  ── 用戶端 / H5 回填頁      │
  管理員   ──瀏覽器──▶  │  Admin UI（同倉庫 admin 路由）               │
                        └──────────────┬──────────────────────────────┘
                                       │ HTTPS (JWT)
                        ┌──────────────▼──────────────────────────────┐
                        │            FastAPI 後端 (Render/Railway)      │
                        │  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
                        │  │ 用戶服務  │ │ 採集服務  │ │ 投遞服務      │ │
                        │  │ 文檔服務  │ │ 匹配服務  │ │ 通知服務      │ │
                        │  │ 畫像服務  │ │ 管理服務  │ │ 人工接管      │ │
                        │  └────┬─────┘ └────┬─────┘ └──────┬───────┘ │
                        │  ┌────▼────────────▼────────────▼───────┐   │
                        │  │  調度器 (APScheduler) + DB 任務隊列    │   │
                        │  │  採集 Worker / 投遞 Worker (Playwright)│   │
                        │  │  LLM 客戶端（可切換 provider）         │   │
                        │  └────────────────────────────────────────┘ │
                        └───────┬──────────────┬──────────────┬────────┘
                                │              │              │
                     ┌──────────▼───┐  ┌───────▼──────┐  ┌────▼────────────┐
                     │ Supabase      │  │ Cloudflare R2 │  │ 外部渠道         │
                     │ Postgres+Auth │  │ 附件存儲 10GB │  │ PushPlus/企業微信 │
                     │ +Storage 500MB│  │ (免出口流量)  │  │ SMTP(Brevo)      │
                     └──────────────┘  └──────────────┘  └─────────────────┘
```

## 2. 技術棧

| 層 | 選型 | 理由 |
|---|---|---|
| 後端 | Python 3.12 + FastAPI | 爬蟲/RPA（Playwright）、LLM 生態最成熟 |
| ORM/遷移 | SQLAlchemy 2.x + Alembic | 管理員可審計 schema 變更 |
| 前端 | React 18 + Vite + shadcn/ui + Tailwind | 快速出管理/用戶兩套界面 |
| 數據庫 | Supabase Postgres（免費 500MB） | Auth/Storage/RLS 一體，最省事 |
| 附件存儲 | Cloudflare R2（10GB 免費、免 egress） | Supabase Storage 1GB 免費作備選/小文件 |
| 自動化 | Playwright (Python, Chromium) | 反檢測優於 Selenium；支持多瀏覽器上下文隔離用戶登錄態 |
| 任務隊列 | 自研 DB 隊列 + APScheduler | 免費層不再引入 Redis；後續可平滑換 Celery/Arq |
| LLM | 可插拔（DeepSeek / OpenAI / 其他 OpenAI 兼容 API） | 簡歷解析、畫像、匹配評分、微調、Cover Letter |
| OCR（僅掃描件） | PaddleOCR（開源免費） | 掃描版 PDF/圖片兜底；數字版 PDF 直接抽文本 |
| 部署 | Render / Railway 免費層 + UptimeRobot 保活 | Supabase Free 無活動 1 週休眠，需每日心跳 |
| 推送 | PushPlus / 企業微信機器人 / SMTP | 額度已核實，見《03》 |

## 3. 模塊職責

| 模塊 | 職責 | 關鍵接口 |
|---|---|---|
| 用戶服務 | 註冊登錄（Supabase Auth）、profile、設置、平台帳號加密庫、關注公司 | `/auth/*`, `/me/*`, `/accounts/*`, `/companies/*` |
| 文檔服務 | 上傳/刪除/替換文件、文本抽取、LLM 結構化、簡歷版本管理 | `/documents/*`, `/resume-versions/*` |
| 畫像服務 | 生成/更新用戶畫像、適合崗位報表 | `/profile-report/*` |
| 採集服務 | 適配器架構、每日採集、登錄態管理、崗位入庫去重 | `/collect/*`（內部+管理） |
| 匹配服務 | 硬性過濾 + 貼合度評分、閾值篩選 | `/matches/*` |
| 投遞服務 | 狀態機、表單映射填充、附件上傳、截圖存證、重試 | `/applications/*` |
| 人工接管 | 驗證碼/登錄/缺字段/缺附件 → 建任務 → 推送 → H5 回填 → 繼續投遞 | `/manual-tasks/*` |
| 通知服務 | 每日摘要、投遞結果、失敗告警、H5 連結生成 | `/notifications/*`（內部） |
| 管理服務 | 用戶審計、適配器健康、成功率報表、全局配置、審計日誌 | `/admin/*` |

## 4. 關鍵流程設計

### 4.1 每日採集流水線

```
00:30(UTC+8) 調度器觸發
 → 合併全部用戶(關注公司 + 已配置平台帳號) 去重 → 生成採集任務
 → 採集 Worker 逐來源執行：公司官網 / ATS API(有公開職位API的用API，如 Greenhouse/Lever)
   / Playwright 爬取(Workday等動態頁) / 平台帳號登錄後採集(獵聘/Boss 二期)
 → 解析 JD → 入庫 job_postings(按 來源+外部ID 去重，標 is_active)
 → 對每用戶新增崗位跑匹配 → 生成 job_matches
 → 失敗重試 3 次 → 記入 collect_jobs 錯誤
```

### 4.2 貼合度評分（雙層）

1. **硬性過濾層**（規則+LLM 抽取）：從 JD 抽取硬性要求（學歷、專業、年限、簽證、證書、語言），與用戶畫像逐項比對；任一不滿足 → 匹配記錄標 `hard_failures`，不進入自動投遞，僅在推送中提示「因 XX 不滿足被過濾」。
2. **評分層**（LLM）：綜合技能重疊、經歷相關性、職級、地點、薪資偏好，輸出 50–100 分 + 三條可解釋理由 + `score_breakdown`。

### 4.3 投遞狀態機

```
                    ┌──────────────┐
   閾值達標 ──────▶ │   queued     │
                    └──────┬───────┘
                           ▼
                    ┌──────────────┐   前置檢查失敗(缺關鍵字段/附件/登錄態)
                    │  in_progress │───▶ needs_input ──▶ 人工接管任務 ──▶ answered ──┐
                    └──┬───────┬───┘                                               │
              提交成功 │       │ 平台報錯/網絡錯誤                                    │
                       ▼       ▼                                                    │
                ┌────────────┐ ┌──────────────────┐  重試3次仍敗  ┌──────────────┐  │
                │ submitted  │ │ failed_retryable │ ────────────▶ │  aborted     │  │
                └────────────┘ └──────────────────┘               └──────────────┘  │
                       ▲                                                             │
                       └─────────────────────────────────────────────────────────────┘
   終態: submitted / aborted / duplicate_skip / not_supported
   每次狀態變更 → audit_logs + 推送(按用戶渠道)
```

- 冪等保證：`unique(user_id, posting_id)` 於 applications；提交前二次檢查外部平台是否已有申請記錄。
- 速率限制：每用戶每 5 分鐘最多 1 次投遞（免費層 + 防風控）。

### 4.4 人工接管流程

```
投遞 Worker 遇到: 驗證碼 | 登錄失效 | 缺失關鍵字段 | 缺附件
 → 暫停該 application(in_progress 掛起) → 建 manual_task(附問題、選項、截圖)
 → 推送用戶(帶 H5 連結) → 用戶填寫/操作
 → H5 回填 → 更新 answer → 觸發重試(30 分鐘內) → 繼續原步驟
 → 任務 48h 未處理 → expired, application → aborted
```

### 4.5 每日推送

- 時間：用戶設置（默認 08:00 用戶時區）。
- 內容：① 新增匹配崗位（≥閾值）Top N + 連結 ② 昨日投遞結果匯總 ③ 待處理人工任務入口 ④ 登錄態過期提醒。
- 渠道優先級：微信（PushPlus）→ 企業微信 → 郵件；單渠道失敗降級。

## 5. 安全設計

| 項 | 方案 |
|---|---|
| 平台帳密 | AES-256-GCM 信封加密：每用戶 DEK（Data Encryption Key）加密明文，DEK 用服務端 KEK（環境變量，不入庫）包裹後存 `key_wraps`；解密僅發生在投遞 Worker 內存中 |
| 登錄態 | 平台 Cookie/Storage 快照加密存 JSONB；定期探活，失效標記並推送 |
| 多租戶隔離 | Supabase RLS（所有表 `auth.uid() = user_id`）+ FastAPI 依賴注入強制 user_id |
| 審計 | 所有狀態變更、管理員操作、登錄事件寫 audit_logs |
| 日誌脫敏 | 中間件自動替換密碼/Cookie/token 字段 |
| 法律文件 | 用戶協議、隱私政策、代投授權書（註冊時強制勾選） |

## 6. API 風格與主要端點

- REST + OpenAPI（FastAPI 自動生成）；JWT Bearer；分頁 cursor 風格。
- 主要資源：`/auth /me /settings /documents /resume-versions /accounts /companies /profile-report /jobs /matches /applications /manual-tasks /notifications /admin/users /admin/adapters /admin/stats`。

## 7. 部署拓撲（免費層）

| 組件 | 平台 | 說明 |
|---|---|---|
| 後端 + 前端靜態 | Render/Railway free web service | 單進程同時起 API + APScheduler + 輕量 Worker |
| 數據庫 | Supabase Free | 2 個項目：dev + prod |
| 附件 | Cloudflare R2 | 簽名上傳（前端直傳，繞過後端帶寬） |
| 保活 | UptimeRobot 免費監控每 5 分鐘 ping `/healthz` | 防 Render 冷啟動 + Supabase 休眠 |
| 密鑰 | Render 環境變量 / Secret 文件 | KEK、各平台 API key |

## 8. 監控與告警

- `/admin/stats`：每日採集量、匹配量、投遞成功率、人工任務積壓、LLM token 費用。
- 健康檢查：各適配器近 24h 成功率；連續失敗告警推送管理員。
- 錯誤聚合：collect_jobs/application_attempts 錯誤碼統計。

## 2. 搬到新機器的兩種方式

### 方式 A：GitHub 拉取（推薦，最簡單）

新機器只需安裝 git + uv + 網絡，然後：

```bash
git clone https://github.com/lelouchma0725-design/jobfly.git
cd jobfly
bash scripts/setup-dev.sh        # 自動：uv 環境 + 依賴 + Node22 + Playwright
```

然後把 `backend/.env`（含密鑰）從舊機器複製到 `backend/.env`，
或手工填寫（模板 `backend/.env.example`，KEK 用舊機器同一個值，否則已加密數據無法解密）。

### 方式 B：物理複製（無網絡環境）

複製這些目錄/文件即可：

```
docs/  scripts/  .gitignore  render.yaml  README.md  Dockerfile
backend/{app, alembic, tests, pyproject.toml, .env.example, .env, Dockerfile}
frontend/{src, package.json, tsconfig.json, vite.config.ts, index.html, pnpm-workspace.yaml, .env.example}
```

運行環境（venv/Node/Playwright）在新機器上用 `scripts/setup-dev.sh` 重建。

## 3. 部署（新機器 → 生產）

| 場景 | 步驟 |
|---|---|
| 只跑本地開發 | setup-dev.sh + backend/.env + `uvicorn app.main:app --reload` + 前端 `pnpm run dev` |
| 部署生產 | 照 [05-部署運維.md](05-部署運維.md)：Render 服務連 GitHub 倉庫（代碼已含全部修復），密鑰通過 Render 環境變量注入（清單在 render_deploy.py 腳本內） |
| 換另一台服務器 | 方式 A clone + `render_deploy.py` 或手動 Blueprint |

## 4. 可用性結論

✅ **可以使用**。生產站點（https://jobfly-frontend.onrender.com）目前就跑在 GitHub 倉庫的代碼上，
且部署驗證 16/17 通過；倉庫代碼與本地完全一致（每輪提交後均同步）。
唯一需要人工保管的是 `backend/.env` 中的 KEK_BASE64 與各密鑰——**KEK 丟失將無法解密用戶的平台帳號密碼**。

## 5. 密鑰清單（backend/.env 內容，備份時對照）

SUPABASE_URL / SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY / DATABASE_URL（東京區連接池）/
KEK_BASE64（⚠️ 最重要）/ R2_ACCOUNT_ID / R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY / R2_BUCKET /
LLM_API_KEY / OPS_SECRET / ADMIN_EMAILS

# 版本管理規範

## 版本命名
- 大版本（功能里程碑）：V0.5、V0.6、V0.7 …（每次重大功能更新 +1）
- 線上環境（Render + Supabase）始終運行最新版；GitHub main 分支為唯一真源

## 發佈流程（每次大版本更新執行一次）
1. 代碼提交並推送 GitHub main
2. 更新 `VERSION` 文件（根目錄）
3. 打兩個標籤：
   - 上一版標籤（如 `v0.5`）→ 指向更新前的最後一個 commit（歷史留檔）
   - 新版標籤（如 `v0.6`）→ 指向新 HEAD
4. GitHub 創建 Release（附變更說明），自動生成源碼 zip 供下載備份
5. 部署 Render（backend + frontend）並驗證線上

## 本地更新方法（用戶側）
- 若本地是 git clone：`git pull` 後刷新瀏覽器擴展（chrome://extensions → 刷新）
- 若只下載過 zip：從 GitHub 下載最新 main zip（https://github.com/lelouchma0725-design/jobfly/archive/refs/heads/main.zip）覆蓋本地
- 敏感文件（backend/.env 等）在 .gitignore 中，不會被覆蓋或洩露
